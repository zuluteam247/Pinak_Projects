# Local container deployment contract

The image installs no optional embedding model. Its default `PINAK_EMBEDDING_BACKEND=none` is keyword-only, not semantic vector search. `/api/v1/health` reports `embedding_backend`, `vector_enabled`, and the configured model when vectors are enabled. Do not set `dummy` for a real deployment. A real embedding deployment needs a separate image with the `embeddings` extra installed and model artifacts available; a missing extra/model must stop startup, not fall back to dummy. An existing index also needs a model/version compatibility check before changing its backend; this is not yet implemented.

Run Compose from `Pinak_Services` after setting a strong, non-default `PINAK_JWT_SECRET` in the environment. The required variable prevents Compose from starting with an absent secret. The service binds only to loopback port 8001 and persists data in `memory_service/data` via the image's `PINAK_DATA_ROOT`. The image is built using the repository root as context, matching the Dockerfile COPY paths. Redis was removed because this service does not use it. The healthcheck calls readiness, which remains unready while verification is incomplete or skipped.

Exactly one process may own a data directory. The image runs one Uvicorn worker, and startup holds an exclusive local `flock` on `.pinak-writer.lock` for the service lifespan. A second process using the same local directory fails startup before opening the database or index. Do not scale Compose replicas, run additional workers, or point multiple hosts/containers at a shared volume. `flock` is not a distributed lease; network filesystems and replicated copies of the same SQLite/index data are unsupported. Back up and restore to a single owner; test recovery before serving traffic. This is a single-node boundary, not a high-availability design.
