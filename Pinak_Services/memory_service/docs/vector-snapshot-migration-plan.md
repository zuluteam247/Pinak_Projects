# Vector snapshot format migration (review draft, not a deployment instruction)

The old `vectors.index.npy` is an object-array pickle. Do not unpickle it in the service, CLI, backup process, test runners, or migration helper. The new code refuses this file at startup. The safe numeric-only snapshot uses an uncompressed `.npz` envelope at the configured path, with `format_version=1`, float32 vectors and int64 IDs.

Release gate for each dataset:

1. Quiesce its sole writer and block API traffic. Preserve the old SQLite DB, WAL/SHM if present, legacy index bytes, config and deployment revision without opening the index with pickle. Make a filesystem-level copy of a stopped dataset and compute SHA-256 for each original and copy. A DB-only SQLite online backup while the writer is active does not establish a paired index snapshot. Keep the original read-only for rollback; do not run the old backup helper, since it unpickles the index.
2. Run SQLite `PRAGMA integrity_check`, check the migration ledger and enumerate semantic, episodic and procedural rows with non-null `embedding_id`. Reject duplicate IDs across all three tables. Confirm the exact prior embedding model identifier, version, tokenizer, normalization and dimension from trusted deployment records and runtime config, not from the pickle. If this cannot be established or the encoder artifacts are unavailable, stop. Never substitute dummy vectors in a real dataset.
3. In a separate scratch data directory only, load the copied DB and the verified encoder. Re-encode all indexed rows from the canonical DB content with the same text-building rules as `MemoryService.verify_and_recover`, in bounded batches. Write the new numeric snapshot to a temporary file and `fsync` it and its directory. Check uniqueness and exact ID set, vectors' finite float32 shape and model dimension, and the snapshot reader's bounds. Compare recall for a fixed test-query set against a separately trusted baseline; do not claim equivalence without one.
4. Run the new backup/verify path against the scratch DB and numeric snapshot, and restore that backup into another disposable directory. Verify IDs, backup checksums, SQLite integrity, startup readiness and recall. Record counts, paths, digests, model identity, CI revision and reviewer sign-off. Only after a reviewed cutover plan, install the new service and pair in one stopped-writer window. Keep the original copies, do not delete or unpickle them.
5. Roll back by stopping the new writer and restoring the entire original DB/index/config pair to the old reviewed code, not by mixing old and new files. Any failed migration leaves original bytes untouched and requires operator review before retry.

Open release questions: current repo has no persisted embedding-model fingerprint paired to snapshots; a configured model name alone does not prove artifact identity. The reader bounds dimension but backup/doctor/TUI cannot compare to a trustworthy configured dimension without one. This needs a model/manifest design and real dataset inventory before deployment.

Reader capacity: the candidate caps the outer file at 64 MiB, total member allocation at 60 MiB, rows at 30,000 and dimension at 4,096. NumPy and reconciliation copy arrays and compute norms, so live memory exceeds the file size; the limits are a conservative starting point for the reported 16 GB Mac, not a measured load test. Inventory the actual dataset size and benchmark peak RSS before accepting these values. Oversized data needs a reviewed format/storage redesign, not an ad hoc cap increase.

Custody: parsing the same open file handle and checking file metadata before/after detects ordinary races but does not authenticate bytes. A `zulu`-writable parent or hardlink can be changed by the same user. Require quiesced sole-writer data directory, account and mode inspection, a verified backup and hashes; no claim of protection against a hostile same-user actor. Diagnostic readers may confirm shape and ID count, not embedding-model identity; no backup or doctor report proves model compatibility until a committed model fingerprint/manifest is built and checked.
